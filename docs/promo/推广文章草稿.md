# Prometheus 撑不住了？我是如何用 VictoriaMetrics 把存储成本打下来的

## 开头（痛点共鸣，300字）

- 场景：Prometheus 用了两年，series 涨到几百万，内存天天报警，WAL 损坏过两次，
想查三个月前的数据——不好意思，retention 只设了 15 天。
- Thanos/Cortex 看过，架构太重，一个小团队运维不起。
- 转折：换了 VictoriaMetrics 单机版，同样的机器，retention 直接拉到 12 个月。

## 第一部分：为什么是 VictoriaMetrics（500字）

- 三个数字：存储占用约 1/7、内存约 1/7、高基数专门优化（官方数据，附文档链接）。
- 关键认知：**单机版先行**——官方建议每秒百万点以下别碰集群版，
很多人一上来就上集群，是过度设计。
- vmagent：采集和存储解耦，Prometheus 抓取配置语法直接复用，零学习成本。

## 第二部分：一条命令起全栈（800字，一步一图）

- `git clone` → `cp.env.example.env` → `docker compose up -d`
- 截图：Grafana 总览看板、vmui 查询界面、vmalert 规则页
- 强调：自带 node-exporter，启动即有数据，5 分钟验证整条链路

## 第三部分：已有 Prometheus，怎么不停机迁移（1000字，核心干货）

- 三步法：vmagent 双写 → vmctl 迁历史 → Grafana 切数据源
- 贴双写配置、vmctl 命令、回滚预案表格
- 这部分是全文转发率最高的部分，值得最细的截图

## 第四部分：容量规划——到底要多少机器（500字）

- 速查表：10万/100万/500万 series 对应的内存磁盘 CPU
- 三个省资源的开关：流式聚合、控制 label 基数、retention 分层
- 引导：完整表格在仓库 docs/capacity-planning.md

## 第五部分：网络设备也一起收了（300字，差异化）

- 大多数 VM 教程只讲主机和 K8s，网络设备没人讲
- vmagent 直连 snmp_exporter，MIB 选指标用 snmp-mib-ui 可视化点选
- 一句话带过，感兴趣的去看 docs/snmp-integration.md
