# SNMP Network-Device Integration

This stack's vmagent is natively compatible with Prometheus scrape configs,
so it can scrape `snmp_exporter` directly — switches, routers and firewalls
land in the same VictoriaMetrics as your hosts and K8s metrics:
one query language, one alerting pipeline.

## Pairing with snmp-mib-ui

If you use [snmp-mib-ui](https://github.com/Oumu33/snmp-mib-ui):

1. Browse MIBs visually in snmp-mib-ui and tick the OIDs you need;
2. Pick **SNMP Exporter** as the engine and generate `snmp.yml` in one click;
3. Point snmp_exporter at the generated `snmp.yml` and start it;
4. Uncomment the `snmp` job in this stack's `config/vmagent/scrape.yml`,
   set the targets to your device IPs.

```yaml
# config/vmagent/scrape.yml
- job_name: "snmp"
  static_configs:
    - targets: ["192.168.1.1", "192.168.1.2"]  # your device IPs
  metrics_path: /snmp
  params:
    module: [cisco]   # must match a module name in snmp.yml
  relabel_configs:
    - source_labels: [__address__]
      target_label: __param_target
    - source_labels: [__param_target]
      target_label: instance
    - target_label: __address__
      replacement: "snmp-exporter:9116"
```

Then `docker compose restart vmagent`.

## Verify

In vmui:

```metricsql
# are devices reachable?
up{job="snmp"}

# interface traffic (adjust metric names to your module)
rate(ifHCInOctets[5m])
```

## Multi-vendor tips

- Split modules per vendor (`cisco` / `huawei` / `h3c`) — snmp-mib-ui's
  brand-package management maps to this naturally;
- Interface metric names differ per vendor; use `or` in Grafana queries
  to cover variants, or standardize on the aliases generated by snmp-mib-ui.
